# 狼人杀（联网控制台版）需求文档

状态：**第九轮完成（§19：JOIN 分支空指针修复、命令封装与输出、槽位空洞压缩名单、兜底回滚与 REJOIN、本地用户窗口与在线 NPC 全流程）**（round9_test.ps1 **47 项全 PASS**，含在线 NPC 发言/API/自动入房）。第一至八轮已实现并通过 tests/ 脚本。本文档是编码与验收的唯一依据，修改需求必须同步更新本文档。

## 1. 总体目标

Windows 控制台程序，MSVC C++ 实现，三进程联机架构（完全复用 `reference/demon/` 已验证的骨架）：

- `Start.exe` 房间管理器（可选端口参数 `Start.exe [端口]`（非法参数直接中文报错退出）；**无参数时启动交互输入监听端口**（提示「请输入监听端口（1024-65535）：」，非法输出具体原因后重新输入，EOF 退出），§18.4）
- `Server.exe` 单局游戏服务器（每局一个进程，由 Start 拉起）
- `Client.exe` 客户端（大厅 → 房间 → 游戏）
- `common.h` 共享工具头（直接复用参考项目：`ReceiveLines`、`SanitizeName`、`IsValidPort`、`SetConsoleUtf8`、`DisableConsoleQuickEdit`、`ClearScreen`、`LogMsg` 等）

所有端 UTF-8 编码（`SetConsoleUtf8` + `/utf-8` 编译），关闭快速编辑/文本选择（`DisableConsoleQuickEdit`），全程中文提示。

## 2. 房间系统（比恶魔轮盘更完善）

### 2.1 基本能力
- 房主建房（自选端口 1024–65535），其他玩家按端口加入；房间上限 **12 人**。
- 用户名全局唯一（**重名直接拒绝**）：`NAME` 时服务端遍历全房/全连接查重；建房、入房时的当前名字同样受查重约束。客户端本地也先校验提示。
- **名字规则**（客户端与服务端双重校验，规则一致，均为 `common.h` 同一实现）：
  - 限 **10 码点**（`MAX_NAME_CHARS=10`，按 UTF-8 码点计数，汉字一字一码点、不劈字；超长按 `SanitizeName` 净化并截断）。
  - **禁止 IP 格式**：合法 IPv4（`IsIpAddress`，拒绝前导零）与「点分数字形似」串（`LooksLikeIpName`）一律驳回；判定在长度截断前进行，防止超长 IP 被截断后漏检。
  - 重名、拉黑、TRANSFER/PICK 等名字比对一律**大小写不敏感**（`NameEquals`）。
- 准备不自动开局：房主输入 `START`、或开启 **AUTO** 后全员 READY，人数 ≥ 4 才开局（无倒计时，直接拉起 Server.exe；比例不符时走 §2.5 自动配置确认流程）。
- 房间内普通打字 = 聊天（公开频道广播给房内所有人）。
- `LIST` 显示房间列表（含人数、游戏中标记）；`STATUS` 显示本房成员与准备状态（**竖排显示**：槽位 | 名称 | 是否准备，需美观对齐并统一更新所有端包括中英客户端）。
- **STATUS 竖排显示要求**：
  - 格式示例（等宽对齐）：
    ```
    ID  | NAME        | ST
    1   | lyh         | 1
    2   | 石子轩      | 0
    3   | Alice       | 1
    ```
  - 槽位列（ID）：数字，右对齐，半角 1 宽。
  - 名称列（NAME）：字符串，左对齐，全角字符算 2 宽；名字列宽取 max(12, 最长名字宽)。
  - 准备状态列（ST）：`1`=已准备，`0`=未准备，右对齐，半角 1 宽。
  - 多行文本经单条 `ROOM_STATUS|` 下发，所有端（Start/Server/Client_cn/Client_en）均需正确渲染。
  - **验收（未完成）**：竖排显示对齐正确，中英客户端输出一致。

### 2.2 转移房主（TRANSFER / 转移）
- 仅房主可用：`TRANSFER <槽号或名字>`，把房主身份转给房内指定玩家；目标玩家收到 `ADMIN|` 提示；转移后原房主失去配置权限。
- 房主离开房间时：槽位最小者顶替房主（参考恶魔轮盘顶替逻辑）。

### 2.3 PICK 指定对象（PICK / 踢）
- 仅房主可用：`PICK <槽号或名字>`，点名踢出指定玩家（不是恶魔轮盘那种固定踢 2 号位）。
- 被踢玩家收到 `KICKED|` 提示并断开；**禁入 10 秒**（按名字记录，期内 JOIN 被拒）。
- 游戏中不能踢人（游戏期间玩家的大厅连接已断开，PICK 目标不存在）。

### 2.4 配置项（仅房主）
| 配置 | 命令（中英双语） | 说明 |
|---|---|---|
| 职业档位 | `LEVEL 0\|1\|2` / `档位 0\|1\|2` | 0 基础 / 1 经典 / 2 豪华，数字越大职业越丰富（见 §3.2） |
| 村民开关 | `VILLAGER 0\|1` / `村民 0\|1` | 独立于档位的村民启用开关，默认 0（关） |
| 狼:中立:神 比例 | `RATIO <狼> <中立> <神>` / `比例 <狼> <中立> <神>` | **真实人数**，非传统比例；非法输入直接失败、不设置 |

- 配置命令输入不合法 → 明确中文错误提示，不修改任何配置。
- `EXIT`/`取消` 在配置会话中用于放弃。

### 2.5 开局前的自动配置（重点验收项）
- 全部玩家 READY 时，若 **人数 ≠ 狼+中立+神**（村民关闭时）：
  1. Start 自动计算一个合法组合（考虑人数上限 12、各阵营职业数量、胜负平衡，见 §4.2 规则）；
  2. 输出自动配置结果并询问房主：`1` 同意 / `0` 不同意；
  3. 同意（`CONFIRM 1`）→ 按新配置直接开局；不同意（`CONFIRM 0`）→ 保持当前比例、全员取消准备并提示修改比例后重新准备，不开局。
- 村民开启时：狼+中立+神 可小于实际人数，差额自动填充村民（合法），仍询问房主确认。

### 2.6 拉黑与开局控制（仅房主）
- `BAN <槽号/名字/IP>` / `拉黑 …`：拉黑玩家或 IP，禁止其（再次）加入本房，直到取消拉黑。
  - 按名字：与 NAME 同规则规范化（净化+截断）后入库，比对大小写不敏感；目标在房则先踢出再拉黑，不在房直接入单（此后加入被拒）。
  - 按 IP：`IsIpAddress` 识别；入单后**立即踢出房内同 IP 玩家（房主除外）**。
  - **游戏进行中不能拉黑**；**不能拉黑自己**。
  - 黑名单随房间销毁（`RELEASE`）一并清除，不跨房间保留。
- `UNBAN <名字/IP>` / `取消拉黑 …`：按名字或 IP 从黑名单移除（名字比对大小写不敏感，与入单规则一致）。
- `START` / `开始`：房主手动开局。不足 4 人 / 有人未准备 / 游戏进行中均拒绝；比例合法直接开局，否则进入 §2.5 确认流程。
- `AUTO` / `自动`：切换「全员准备自动开局」开关；开启瞬间若已全员准备则立即走开局流程。
- `RELEASE <房间号>`：内部指令（Server.exe 在全部玩家失联时发送），销毁房间、清空黑名单。

## 3. 职业系统

### 3.1 职业总表
| 职业 | 阵营 | 技能 |
|---|---|---|
| 狼人 | 狼 | 夜晚刀人；狼群内部私聊 |
| 白狼王 | 狼 | 夜晚刀人；白天可自爆带走一名玩家（立即进入夜晚） |
| 预言家 | 神 | 每晚验一人身份（反馈 狼/好人/中立） |
| 女巫 | 神 | 一瓶解药（救被刀者）+ 一瓶毒药（毒一人），每夜各限一次；首夜可自救，解药与毒药同一夜不可双用 |
| 猎人 | 神 | 被放逐/被狼刀/被自爆炸身亡时可开枪带走一人（全局限一枪）；被毒死时不能开枪 |
| 守卫 | 神 | 每晚守一人免刀；不可连续两晚守同一人；与女巫解药冲突时被守者死亡 |
| 白痴 | 神 | 被放逐时翻牌免死（仅一次），继续存活但失去投票权 |
| 丘比特 | 中立 | 开局连情侣两人；情侣一方死另一方殉情；情侣阵营成为第三方（见 §4.4） |
| 盗贼 | 中立 | 开局从剩余身份卡中二选一（可含狼），选定后按新身份行动 |
| 村民 | 好人（平民） | 无技能，仅投票 |

### 3.2 档位定义
- **档位 0（基础）**：狼人、预言家、女巫、猎人（中立职业不启用）
- **档位 1（经典）**：档位 0 + 守卫、白痴
- **档位 2（豪华）**：档位 1 + 白狼王、丘比特、盗贼
- **村民开关**独立于档位，默认关闭。开局时若开启，村民填充好人空缺。

### 3.3 职业分配（开局，由 Server 执行）
- 按比例得到 狼 W / 中立 N / 神 G（村民开启时余下缺口填村民，否则 W+N+G=人数）。
- 狼：白狼王最多 1 名，其余为狼人（W 人狼阵营）。
- 中立：从启用中立池中**每种最多 1 名**地抽取 N 名（不足则失败，见 §4.2 自动配置兜底）。
- 神：从启用神职池中**每种最多 1 名**地抽取 G 名；G 超过可用神职数量且村民开启时用村民补齐（村民算好人阵营），村民关闭时该组合不合法 → 触发 §2.5 自动配置。
- 分配结果只告知本人（身份保密）。

### 3.4 职业帮助（HELP 系统，重点验收项）
- `HELP` / `帮助`：列出所有命令说明（中文）。
- `HELP <职业名>` / `帮助 <职业名>`：显示该职业详细介绍（技能、阵营）。**职业名支持双语**（如 `HELP 狼人` 与 `HELP werewolf` 等效）。
- **开局显示身份时**，必须同时显示该职业的详细介绍（与 HELP 职业名输出同源）。

## 4. 游戏流程（完整版，Server.exe）

### 4.1 流程总览
```
开局（分配身份+介绍）→ 丘比特连情侣 → 夜晚1（守卫→狼刀→预言家→女巫）
→ 天亮结算（公告死讯/平安夜）→ [白狼王可自爆] → 白天（发言+投票放逐）
→ 猎人/白痴结算 → 夜晚2 … → 胜负判定 → 结算广播 → 通知 Start（GAME_ENDED）
```

### 4.2 夜晚行动（按序执行）
1. **守卫**：输入守谁（每夜限一次；不能连续两晚守同一人；可空守）。
2. **狼人**：狼群私聊频道互通（死亡狼人不能发言，可看）；每狼输入刀人目标编号，**票多者被刀**，平票随机。
3. **预言家**：验一人，只把结果告诉本人（`狼人/好人/中立`）。
4. **女巫**：先救（看到被刀名单后决定）再毒（每项各一次、首夜可自救、救毒不可同夜）。

结算顺序：守卫免刀 > 女巫救（守卫与救冲突 → 死亡）> 狼刀 > 女巫毒。公告结果。

### 4.3 白天阶段
- **发言**：存活玩家自由打字聊天（公开），死亡玩家静默（只能看）。服务器把非命令文本广播。
- **投票**：每人 `VOTE <编号>` / `投票 <编号>`（可弃权：直接回车或 `VOTE 0`）。全员投票后统计，**票多者被放逐**，平票无人放逐。
- 被放逐者若为白痴 → 翻牌免死（失去投票权）；若为猎人 → 开枪带走一人；否则死亡并公告。
- **白狼王自爆**：白天任意时刻 `BOMB` / `自爆`（指定一人带走），立即进入夜晚；夜晚死人时白狼王不能自爆（只能夜晚死）。

### 4.4 胜负判定（每阶段结算后检查）
- 狼阵营全灭 → **好人阵营胜**。
- 狼阵营人数 ≥ 好人阵营人数 → **狼阵营胜**。
- 丘比特情侣成为第三方（情侣为一狼一好人时）：情侣全存活且场上其他阵营只剩一方 → **情侣阵营胜**；情侣死亡 → 恢复原阵营判定。
- 盗贼：选择身份后按新身份所属阵营参与判定。
- 无人能行动的死局（如只剩两人且互不对立）→ 判平局。

### 4.5 断线重连（复用恶魔轮盘全套机制）
- 游戏中断线：重连 3 次（间隔 5s）→ 失败发 `GIVEUP|N` → 本局中止 → 全员回房。
- 任一玩家断线期间，其他人等待最多 25 秒；超时/放弃 → 本局中止，房间保留。
- 游戏结束：Server 通知 Start（`GAME_ENDED`），房间**保留**为结束等待态；各客户端重连 RM 后自动发送 `GAME_ENDED + REJOIN` 回原槽位（房主按槽 0 保留身份）；若房间已被 `RELEASE` 销毁则回房失败落在大厅。
- 大厅断线/重连失败：3 次重试后 Pause 并退出。

## 6. 界面与提示规范
- 全程中文提示；英文命令名仅作为命令语法的一部分显示在帮助中。
- 控制台 UTF-8、无乱码；快速编辑已关闭（框选不冻结）。
- 开局身份展示：`你的身份：狼人` + 职业详细介绍。
- 所有非法输入（重名/非法端口/非法比例/非法档位/非法槽号/非职业名）均给出明确中文错误提示，不崩溃。

## 7. 协议设计（沿用 `|` 分隔 + 换行结尾）
- Start 接收（Client 或 Server.exe 发送）：`HELLO|3`（握手，3=协议版本号）、`NAME|<n>`、`LIST`、`CREATE|<port>`、`JOIN|<port>`、`READY`、`STATUS`、`START`、`AUTO`、`TRANSFER|<槽号或名字>`、`PICK|<槽号或名字>`、`BAN|<槽号/名字/IP>`、`UNBAN|<名字/IP>`、`LEVEL|<0|1|2>`、`VILLAGER|<0|1>`、`RATIO|<W>|<N>|<G>`、`CONFIRM|<1|0>`、`EXIT`、`GAME_ENDED|<roomId>`（Server 通知本局结束）、`REJOIN|<roomId>|<playerId>`、`RELEASE|<roomId>`（全部玩家失联时 Server 通知销毁房间）。
- RM→Client：`WELCOME|`、`NAME_SET|<名字>`、`ROOMS_LIST|`、`CREATED|`、`JOINED|`、`ADMIN|`、`ROOM_MSG|`（聊天/公告）、`READY_STATUS|`、`ROOM_STATUS|`、`CONFIG_NEED_CONFIRM|<狼>|<中立>|<神>`（自动配置建议，仅房主收到）、`GAME_PREPARE|<port>|<roomId>|<ip>|<playerId>`、`GAME_ENDED|<id>`、`REJOIN_FAIL|`、`KICKED|`、`LEFT_ROOM|`、`ERROR:`。
- Server 命令行：`Server.exe <gamePort> "<name1>" "<name2>" ... "<nameN>" <startIp> <startPort> <roomId> <W> <N> <G> <level> <villager>`（变长名字，CJK 走 `CreateProcessW`→`CommandLineToArgvW` 链）。
- 游戏连接：`PLAYER_ID|N`、`PLAYER_<N>|<文本>`（含 `VOTE|`/`BOMB|` 游戏命令）、`GIVEUP|N`、`ROLE|<职业enName>`（身份私发）、`RESULT|<文本>`（验人等结果回显），控制消息 `__CLS__`/`__PAUSE__`/`__INPUT__`/`__PROGRESS__`/`__TYPEWRITER__` 全沿用。

## 14. 第五轮：白天输入体验 / 游戏结束直接回房 / 房主查询命令（2026-08-06 用户报告两类问题并提出新命令需求，本契约为实现依据）

> 背景：子代理调查结论（作为本契约的事实依据）——
> 1. 「白天个别客户端无法输入（尤指预言家）」根因：服务端 `__DAY_OPEN__` 只发给**存活**玩家（死亡静默是狼人杀规则，必须保持，防死者报验人信息破坏平衡）；死亡玩家客户端门控全程 Closed，输入线程在 Client.cpp:452 静默吞键（无回显、无提示、无光标），玩家感知为「无法输入」。预言家是狼人首刀优先目标，故概率最高。**修复方向：让死亡静默可感知**（死亡提示），而非放开死者发言。
> 2. 「重连一直失败（最后才回房）」根因：游戏**正常结束**时 Server 关闭连接的收尾被客户端误判为断线 → 对已退出的 Server 做 3 次必败重连（约 18 秒）→ 才 GIVEUP 回房；回房本身一次成功。另有隐患：客户端把「TCP 连上即算重连成功」（不等服务端确认，遇 `ERROR:already connected` 会陷入连上→被踢循环）；Client.cpp:919 的 `msg == "Game over."` 精确匹配为死代码（服务端实际文案是「本局结束，即将返回房间。」，永不命中）。**修复方向：Server 收尾发终态控制行 `__GAME_OVER__`，客户端收到直接回房**。

### 14.1 白天输入体验（问题 1）
- 保持设计：`__DAY_OPEN__` 仍只发存活玩家（§10.3），死亡玩家白天静默。
- Server：玩家死亡（狼刀 `KillPlayer` 或白狼王自爆）时对死者本人单播一条死亡提示「你已死亡，白天无法发言，可观看局势。」（走现有本地化单播，中/英文版各自文案）。目的是把「无声吞键」变成可感知提示。
- Server：白天 10 秒重发 `__DAY_OPEN__` 的条件去掉 `voteTarget < 0`，改为对所有存活玩家重发（已投票玩家窗口本就不关，重复开窗幂等无害；消除未来任何强制关窗路径下的失声缺口）。
- Client（防御性加固）：`__PAUSE__` 结束后按 `g_dayTalk`/`g_inputSolicited` 恢复门控，而非硬置 `Closed`（当前 Server 不发 `__PAUSE__`，仅消除潜在「暂停后永久失声」）。

### 14.2 游戏结束直接回房（问题 2）
- Server：正常收尾路径（广播「本局结束，即将返回房间。」后、关闭各连接前）向每个客户端发送一行终态控制行 `__GAME_OVER__`（裸行、无参数）。
- Client：
  - 收到 `__GAME_OVER__` → 置已收终态标记、清游戏内状态，**直接走回房流程**（不进入游戏重连）。
  - `__CONN_LOST__` 处理时若已收终态标记 → 跳过 `HandleGameReconnect` 直接回房。
  - 修复死代码：`msg == "Game over."` 精确匹配改为包含匹配（同时匹配中文「本局结束」与英文 `Game over`）作双保险。
  - `HandleGameReconnect`：发出 `PLAYER_ID|k` 后**等待服务端确认**（带短超时）；收到 `ERROR:already connected` 或超时/EOF 计一次失败而非成功，3 次失败走 GIVEUP——杜绝「连上→被踢→再连」假成功循环。
- 效果：正常结束局回房耗时从约 18 秒降为秒级；真断线局重连一次成功。

### 14.3 IP 命令（房主专属）
- 语法 `IP <玩家名>`；仅房主可用，非房主 clean 拒绝（文案同其他房主命令）。
- 匹配：当前房间槽位按 `NameEquals` 大小写不敏感匹配（含游戏进行中保留的槽位：玩家进游戏后名字/IP 保留在槽位中，可查）。
- 成功输出 `ROOM_MSG|`：`<玩家名> 的 IP：<ip>`；未找到 → clean 报错「未找到玩家 <名>」。
- **验收（未验证）**：该命令在游戏进行中与游戏结束后均应可用（不应出现「GameOnly」提示）。

### 14.4 LG 命令（房主专属，房间玩家历史记录）
- 语法 `LG`（无参数）；仅房主可用。
- 记录：Room 内维护 `vector<PlayerLog>{ name, ip, in }`，与黑名单一致随房间销毁。
  - 房主建房、玩家 JOIN/REJOIN 成功 → 按 name（`SanitizeName` 规范化 + `NameEquals`）upsert：已存在则更新 ip、置 in=true；不存在则追加。
  - 玩家**真正离开**（游戏外断开 / 被踢 / 主动退出，即 `RemovePlayerFromRoom` 非游戏期分支）→ 该记录 in=false（记录保留）。
  - 游戏期断开（§13 保留槽位语义）→ 不改变 in。
- 输出格式（等宽对齐：半角 1 宽、全角 2 宽；名字列宽取 max(12, 最长名字宽)，IP 列宽 18 或 max(16, 最长 IP 宽+1)）：
  ```
  Log List
  lyh         10.100.126.14       [in]
  石子轩      196.168.120.10     [out]
  ```

### 18.1 PLIST 人数错误根因一：Client 解析把总数当名字（必现）
- 根因：`Client.cpp` 解析 `PLAYER_LIST|4|Alice|Bob|Cathy|Dave` 时 `substr(12)` 剥离前缀后**没有跳过首字段「总数」**，把 `"4"` 当第一个玩家名缓存 → 名单 N+1 项、显示多一行、所有名字错位 1 槽、「（你）」标记落在上一名玩家身上、自己名字消失。
- 修复：解析时先读并丢弃首字段（总数），再按总数取 N 个名字（字段数不符时以总数为准截断/拒绝，防御畸形行）。
- 验收：`PLAYER_LIST|N|...` 解析后缓存恰为 N 个名字、顺序与行内一致。

### 18.2 PLIST 张冠李戴根因二：Start 的 pid=槽号+1 与 Server 的 pid=名单序错位（槽位空洞时）
- 根因：`StartGameServer` 组装 Server 参数名单时按**槽位升序跳过未连接槽位**（压缩名单），但 `GAME_PREPARE` 下发的 pid 却是 `槽号+1`；Server 的 playerId = **名单中的位置**（1..N）。正常紧凑房间两者一致；一旦槽位出现空洞（开局前某玩家离开，槽位保留空洞；REJOIN 撞槽回落等），`GAME_PREPARE` pid 与 Server 名单序号错位 → 玩家按错误身份进游戏（张冠李戴）、超界 pid 被 Server 拒连。
- 修复：开局时给每个已连接槽位分配**游戏身份号 gamePid = 压缩名单序号（1..N）**（Slot 新增 gamePid 字段）；`GAME_PREPARE` 的 pid 用 slot.gamePid；`REJOIN|<roomId>|<playerId>` 按 gamePid 匹配回**原槽位**（不再是 pid-1），匹配失败才回落空槽；房主保护（hostPid=1，槽 0 恒为名单首位）语义不变；清槽时 gamePid 归零，开局分配时覆盖。
- 验收：紧凑局与空洞局（5 人房离开 1 人后 4 人开局）GAME_PREPARE pid、PLAYER_LIST 行、Server 欢迎语、白天广播名字四者全部对齐。

### 19.1 BAN/UNBAN 支持通配符（名字与 IP）
- 模式语法：`*` 匹配任意位数（含 0 位）；`?` 匹配恰好 1 位。**半角与全角等效**：`＊`（U+FF0A）≡ `*`、`？`（U+FF1F）≡ `?`（参数解析时先规范化为半角）。
- 名字模式：如 `BAN Tech*` 拦所有以 Tech 开头的名字、`BAN ???` 拦所有恰好 3 个字符的名字。模式匹配对象是**规范化后的名字**（NAME 同规则净化+截断+大小写不敏感），匹配字符范围即名字白名单字符（中英文/数字/下划线）——不存在【】等白名单外字符（用户澄清：通配符用法举例而已）。
- IP 模式：如 `BAN 10.129.*` 拦整个 IP 段、`BAN 10.*.5.1` 按段通配。匹配对象是玩家当前连接 IP（点分数字串，含前导零异写已按 IsIpAddress 判定后的原串）。
- 存储与匹配：黑名单项带模式标记（`*`/`?` 任意出现即模式项）；JOIN 时名字/IP 均按 glob 匹配（不区分大小写）；**含通配符的模式项不做 NAME 白名单净化**（仅注入清理 `|`/换行/引号 + 长度限制 ≤63），纯名字项保持既有 NAME 规范化路径（兼容）。UNBAN 同语法删除（按模式串字面量精确删除，含通配符时按模式串本身比对）。`.ban` 文件导入支持模式行。
- 匹配命中即拒绝入房（提示沿用现有拉黑提示）；对房内已匹配玩家立即踢出（同 IP 拉黑行为）。
- 原有行为不回归：单字符名可 BAN（`BAN x` 与 `BAN ?` 语义不同：前者精确名 x，后者任意单字符名）；大小写变体、尾随空格、超长截断等既有规则保持。

### 19.2 START /F 强制开局（房主专属）

### 19.4 SHOW / LOOK 命令（两命令完全等效；支持英文 LOOK/SHOW 及中文别名「查看」）
- 语法：`SHOW <子项>` / `LOOK <子项>`。
- 子项与输出：
  - `BAN`：当前黑名单全部名字与 IP（含通配模式），【房主专属】。
  - `RATIO`：当前狼:中立:神比例（含村民开关状态说明）。
  - `LEVEL` / `VILLAGER` / `AUTO`：当前职业档位 / 村民开关 / 自动开局开关。
  - `ADD`：当前本地用户（用户名+控制者）与 NPC（名字+在线/离线）列表，【房主专属】。
- 无参数、未知子项、或该子项无内容可显示（如空黑名单）时：打印 SHOW 命令的用法与作用说明（中英），不报错。
- 大厅（未入房）时：打印用法说明。

### 19.6 ADD USER 本地用户（房主专属，大厅可用，游戏中拒绝）
- 语法：`ADD USER <username> [-u] <玩家名或槽位>`；无 `-u` 时默认分配给房主。-u 位置灵活（username 后任意位置出现即生效）。目标玩家用名字或槽号（槽 1..N）指定。
- username：全服唯一、NAME 同规则校验（白名单/长度 ≥2/防注入/禁止 IP 形似）。
- 效果：username 作为**本地用户**占用一个房间槽位（像真实玩家：可见于 STATUS/LIST/PLAYER_LIST，可被投票/刀/验）；记录 控制者=指定玩家。
- 开局时：Start 为每个本地用户 spawn 一个新控制台窗口运行 `Client.exe <ip> <Start端口> <username> <房间端口>`（自动模式，见 19.8），自动连接→改名→入房→进游戏，由控制者操作；**游戏结束（__GAME_OVER__）后自动退出关闭窗口**。
- 控制者被 PICK 踢出 → 对应本地用户一并移除（若在房）；本地用户被 PICK → 移除本地用户记录。
- 上限：槽位总数 ≤ MAX_PLAYERS(12)（真人+本地用户+NPC 合计）。
