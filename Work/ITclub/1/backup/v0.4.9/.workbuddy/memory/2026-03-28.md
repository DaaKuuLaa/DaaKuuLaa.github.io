## 2026-03-29 修复优化引入的 bug

**问题**: 昨天的性能优化引入了多个严重 bug 导致大量报错且仍然卡顿

**修复内容**:
1. **Worker接口不匹配**: `noise-worker-optimized.js` 只处理 `generate/batch` 类型，但旧调用代码发送 `type:'custom'/'preset'`。在Worker中新增兼容处理。
2. **Worker回调key不匹配**: onmessage 用 `id` 查回调，`_renderCustomViaWorker` 用 `type` 存回调。改为兼容 `id` 和 `type` 两种key。
3. **initAllModules延迟**: 模块3/4分别延迟500ms/1000ms初始化，导致切到对应页面内容空白。恢复立即初始化。
4. **bindEvents延迟**: 模块切换时100ms延迟导致短暂空白，移除。
5. **main.js调用不存在方法**: `setMaxParticles/getMaxParticles` 等方法不存在，精简掉所有无效调用。
6. **performance-detector.js危险代码**: 重写了全局 `getComputedStyle`、`requestAnimationFrame`、`HTMLElement.prototype.offsetWidth/offsetHeight`，严重破坏页面运行。完全重写为仅设置CSS变量的精简安全版本。

## 2026-03-29 第二轮 bug 修复（深度检查）

**问题**: 用户反映仍有报错且网页卡顿

**根本原因与修复**:

1. **noise-calculation.js 双重 DOMContentLoaded 监听**：`initialize()` 内部监听 `DOMContentLoaded`，但外部已在 DOMContentLoaded 中实例化，导致内部监听永不触发，`setupEventListeners()` 从未执行。**修复**：改为直接调用 `setupEventListeners()`。

2. **MutationObserver 监听范围过宽**：监听 `.main-content` 的 `subtree: true`，导致任何子元素（悬浮高亮、滑块等）class 变化都触发回调，产生大量不必要的函数调用。**修复**：改为只监听 `#module-3` 和 `.page[data-page="5"]` 两个元素，不监听 subtree。

3. **initAllModules 加载时初始化所有模块**：`initModule4()` 会立即创建 Worker 并发送渲染请求（500×333px 噪声），用户根本看不到第4页时已在做大量计算。**修复**：`initAllModules` 只初始化第1模块，其他模块在 `moduleShown` 事件（用户切换时）才初始化。`initModuleVisualizations` 增加已初始化标记，避免 Worker 重复创建。

4. **canvas-optimizer 持续 rAF 性能监控**：每帧都运行一个额外的 `requestAnimationFrame` 回调来测量帧时间，本身加重了渲染压力。**修复**：改为用 `requestAnimationFrame` 计帧数 + `setInterval` 每秒统计一次 FPS，大幅降低开销。

5. **main.js 重复的 FPS 计数器**：localhost 下会启动一个 `countFPS()` rAF 循环，与 canvas-optimizer 重复。**修复**：删除该函数。

6. **`regeneratePresetNoise` 防御检查缺失**：在模块4未初始化时调用会抛出 `Cannot read properties of undefined` 错误。**修复**：加 `module4Presets && module4Params` 判断。
