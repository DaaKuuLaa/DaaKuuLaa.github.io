## 一、项目概述

### 1.1 项目定位
本项目是一个沉浸式的Web-based教学演示系统，通过可视化与交互式体验深入解析Perlin Noise（柏林噪声）算法。项目采用现代Web技术栈，注重用户体验与教学效果的平衡，是算法教学从传统PPT向交互式体验升级的优秀范例。

### 1.2 核心目标
- **教学目标**：帮助学习者直观理解柏林噪声算法的核心原理与应用
- **技术目标**：展示现代Web技术（Canvas、毛玻璃效果、模块化架构）在教学中的应用
- **体验目标**：提供沉浸式的16:9影院级学习体验，无滚动、全屏展示

## 四、视觉问题排查工作规范

### 4.1 视觉效果问题排查原则

**核心理念**：不要局限于单一效果，全面考虑所有可能的视觉因素

**问题分析流程**：
1. **识别用户描述**：准确理解用户报告的视觉问题
2. **拓宽排查范围**：不要仅局限于用户提到的特定效果
3. **全面检查相关元素**：
   - 检查渐变覆盖层（::before / ::after 伪元素）
   - 检查背景色变化（hover 状态的 background 属性）
   - 检查阴影变化（box-shadow 的变化）
   - 检查边框变化（border-color 的变化）
   - 检查透明度变化（opacity 的变化）
   - 检查变换效果（transform 的变化）
4. **系统级排查**：确保不遗漏任何可能导致视觉异常的因素

**典型案例**：
- 用户报告"阴影错误" → 实际可能是背景色变化、渐变高亮、边框变化等
- 用户报告"高亮效果" → 可能是渐变层、背景色变化、边框高亮等多种效果的组合
- 用户报告"悬浮异常" → 需要检查所有 hover 相关的 CSS 属性变化

### 4.2 视觉问题修复最佳实践

**修复策略**：
1. **先理解后修复**：在动手修改前，先完整理解问题的所有表现
2. **拓宽排查范围**：不要局限于传统样式认知，考虑所有可能的视觉效果组合
   - 用户描述的"高亮"可能是渐变层、背景色、阴影、边框、位移等多种效果的组合
   - 用户描述的"阴影错误"可能是背景色变化、渐变覆盖、边框变化等其他效果导致
   - 必须全面检查所有 hover 相关的 CSS 属性，而非仅检查用户提到的效果
3. **多维度验证**：修改后检查是否影响其他相关效果
4. **作用域限定**：当需要仅修改特定模块时，使用 ID 选择器（如 #module-3）精确限定作用域
5. **保留其他效果**：确保只移除目标效果，保留其他正常的交互反馈

**修复检查清单**：
- [ ] 确认理解了用户描述的所有视觉问题
- [ ] 检查了所有可能导致该效果的 CSS 属性（不局限于用户提到的效果）
- [ ] 验证了修改不会影响其他模块
- [ ] 保留了正常的交互反馈（阴影、位移等）
- [ ] 在浏览器中实际验证了修复效果

### 4.3 文件修改异常处理规范

**触发场景**：
- 文件内容被意外删除大量内容
- 文件被意外添加大量内容
- 文件结构发生异常变化
- 其他非预期的文件修改

**处理流程**：
1. **立即停止**：发现异常后立即停止当前操作
2. **尝试撤销**：使用 IDE 的撤销功能（Ctrl+Z）恢复到异常前的状态
3. **记忆复原**：如果撤销不可用，根据记忆中的文件原始内容进行复原
4. **禁止直接恢复备份**：不要直接从备份文件夹恢复，因为备份版本可能与当前开发进度不同步
5. **验证复原**：复原后检查文件内容是否完整、正确

**重要原则**：
- ✅ 优先使用撤销操作恢复到异常前的状态
- ✅ 根据记忆复原时，应仔细核对关键代码段
- ❌ 禁止直接从备份恢复（除非万不得已）
- ❌ 不要依赖备份作为首选恢复手段

**预防措施**：
- 在进行大规模修改前，先读取并记录文件当前内容
- 使用小步修改策略，避免一次性修改大量内容
- 每次修改后立即验证效果

## 五、重点规范强调

### 5.1 毛玻璃效果（最重要）

**必须应用的场景：**
- ✅ 所有卡片式内容容器
- ✅ 导航栏与工具栏背景
- ✅ 模态对话框与浮动面板
- ✅ 可视化控制区域

**实现标准：**
```css
/* 必须同时包含以下属性 */
background: var(--glass-bg);           /* rgba(255,255,255,0.08) */
backdrop-filter: var(--glass-blur);    /* blur(12px) */
border: var(--glass-border);           /* 1px solid rgba(255,255,255,0.1) */
box-shadow: var(--glass-shadow);       /* 0 8px 32px rgba(0,0,0,0.3) */
```

**检查方法：**
1. 视觉上应该有半透明模糊效果
2. 边框应该是半透明的，不是纯色
3. 阴影应该从底部投射，颜色是蓝色系而非纯黑
4. 不同层级透明度有差异（0.08、0.06、0.04）

### 5.2 布局约束（严格禁止事项）

**❌ 绝对禁止：**
- 任何导致垂直滚动的设计
- 超过视口高度的内容堆叠
- 页面级滚动条出现
- 需要拖拽滚动条浏览内容
- 内容溢出无处理

**✅ 正确处理：**
- 使用 `overflow: hidden` 禁止滚动
- 内容垂直溢出时，考虑分页或删减内容
- 使用 `calc(100vh - 80px)` 计算可用高度
- 定期检查不同分辨率下无滚动条

### 5.3 色彩系统

**必须使用品牌色系：**
- 主色：`#2962ff`（科技蓝）
- 成功色：`#00c853`（正向反馈）
- 错误色：`#ff5252`（问题标识）
- 文本层级：主白 `#ffffff` → 次文本 `#e0e7ff` → 弱文本 `#b8c2ff`

**禁止使用的颜色：**
- 纯黑背景（应使用深蓝色 `#0a0d1a`）
- 非品牌色系的颜色
- 不透明边框（必须使用半透明）

## 五、常见问题与解答

### Q1: 如何确保不违反"无垂直滚动"的规范？

**A1:**
1. 设计时始终以1920x1080为基准
2. 使用浏览器开发者工具模拟不同分辨率
3. 定期检查 `html, body { overflow: hidden; }` 是否生效
4. 内容过多时考虑分页，而不是增加高度
5. 使用 `calc(100vh - 80px)` 计算主内容区高度

### Q2: 毛玻璃效果不显示或显示异常怎么办？

**A2:**
1. 检查是否同时设置了 `background`, `backdrop-filter`, `border`, `box-shadow`
2. 确认浏览器支持 `backdrop-filter`（Chrome 80+）
3. 检查层级关系，父元素是否设置了 `overflow: hidden` 导致裁剪
4. 使用 `@supports` 查询进行特性检测
5. 参考RULE.md 1.3章节的完整实现示例

### Q3: 日志记录应该详细到什么程度？

**A3:**
参考Log.log中的示例，应该包含：
- 具体的CSS属性变化（如：`max-width: calc(100% - 200px)`）
- 颜色值的具体变化（如：从`#000000`改为`#2962ff`）
- 布局调整的详细描述（如：从横向改为竖向，添加了左侧间距60px）
- 验证过程的具体步骤（如：在1920x1080和1366x768分辨率下测试）
- 使用项目符号列出所有修改点

### Q4: 任务执行中遇到不确定的问题怎么办？

**A4:**
1. 立即停止当前工作
2. 查阅RULE.md相关章节
3. 查看Log.log中类似任务的记录
4. 查看优化效果说明.md中是否有相关说明
5. 如果仍不确定，使用ask_followup_question工具向用户确认
6. 不要凭猜测继续执行

### Q5: 如何确保色彩系统符合规范？

**A5:**
1. 只使用CSS变量（如 `var(--color-primary)`），不要硬编码颜色值
2. 参考RULE.md 1.2章节的色彩定义
3. 检查是否正确使用了功能色彩（success/warning/danger）
4. 文本使用层级色彩系统（text-primary/text-secondary/text-muted）
5. 卡片背景使用毛玻璃变量，不要使用纯色
